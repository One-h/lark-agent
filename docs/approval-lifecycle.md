# 执行审批与会话生命周期

原生命令与宿主工具使用同一套卡片展示与范围语义。群聊隐私的单次确认是独立边界，不能通过普通 turn 许可绕过。

## 授权范围

- **允许本次**：只放行卡片中当前操作或明确展示的当前批次。
- **允许当前任务**：人工许可仅在当前 Codex thread/turn、请求人和审批人绑定仍有效时复用；原生命令与宿主工具可以共享这份许可。
- 新 turn、新请求人、新审批人或会话结束后重新审核。自动审核仍受原有操作类型和目标范围限制，不把只读许可升级成部署许可。
- 待审批请求有效期为十分钟。绿色终态表示许可已获批准，不表示实际执行或部署验证成功。

## 审核背景

自动审核除最新请求外，最多读取六条相同发送人、聊天/话题、Codex thread 的近期历史请求及当时答复；时间范围为六小时，正文总上限2400字符。历史只帮助解释目标、澄清和阻碍，不直接进入快捷匹配，也不是旧许可的继承。

## 结束与断连

- 实际宿主调用前和人工批准时回读原生 thread/turn 状态；仅本地 `running` 记录不足以放行。无法确认原生状态时不开始操作。
- 原生终态通知、调用连接断开、审批过期或服务关闭会终止等待审批；迟到和重放点击不能恢复旧操作。
- 终态通知丢失时，原生状态回读也会收尾本地运行记录并取消待审批；未知状态不被当作确定结束。
- 本地工具桥接没有额外的 fetch 响应头等待期限，等待由审批有效期和真实会话生命周期控制。
- 已经合法开始的外部操作不被宣称为自动撤销或回滚。标准优雅关闭等待其结果落库，不自动重试不确定的部署。

## 回调与升级

手机端仍通过飞书卡片回传交互，不打开本机链接。回调核对审批人、卡片消息和有效请求；HTTP 决策接口 `/v1/approvals/:id/approve`、`approve-turn`、`reject` 必须携带 runtime Bearer 凭据。

宿主审批表兼容新增范围、请求人/thread快照和失败说明。旧记录默认单次许可，不回填为 turn 许可，不重发旧卡片或重跑旧任务。审批历史页展示实际范围与失效说明。

测试中的活跃状态模拟器属于进程内依赖注入，不是网页或 HTTP 设置项。生产默认要求真实原生状态证据。
