# 群内 @ 本人的机器人协同回复

功能默认关闭。全局设置 `ownerMentionAssistEnabled`，单群 `ownerMentionAssistMode` 为 `global/on/off`；单群开启或关闭可覆盖全局，跟随全局时使用全局开关。`ownerMentionAssistOwnerId` 指定被 @ 对象的 open_id，留空使用当前审批接收人；目标必须是个人 open_id。这只是协同对象，不会成为执行请求者。

Forge 入口：设置页的“协同处理群里 @本人的消息”、群聊设置抽屉的“群聊协同”；需本人判断的草稿出现在个人收件箱的独立“群聊协同待确认”区域，确认动作是 **机器人发送文本**，不是以本人身份发送，也不是执行授权。

## 触发与判断

- 必须是群聊、人类发送、真正通过结构化 mention @ 目标对象。昵称文字、引用内容里的 @、@all、本人或机器人发送的消息不触发代理。只 @ 机器人的既有行为不变；同时 @ 对象和机器人仍只派发一次。
- 只处理开启之后的新事件；重复事件不重放，不因配置变化重新执行旧消息。
- 模型在同一个原生 turn 通过 `owner_assist_decision` MCP 判断 `handle/owner_required/ignore`，不额外开一个完整分类会话。尚不知道答案的可调查任务可以接手；需要本人意愿、同意或承诺的事项私下确认；没有回应价值时保持安静。
- 协同会话按群/原生话题、实际发送人和 trust scope 独立复用，不与普通机器人 turn 混发，也不引入个人私聊历史。

## 本人已经回复时

本人新的同群同话题发言按真实消息 ID 追加到当前 turn，仅作为原请求的补充/纠正/停止背景，不改变请求者或授权。等待批准的新操作会暂停，已启动操作不强杀。

最终草稿再次经 MCP 确认，最早在源消息进入后 15 秒发送。若出现新的本人发言，工具返回 `owner_context_updated` 和增量内容；草稿保留，模型检查遗漏、错误、重复后决定补充、私下确认或不回复。再次 `handle` 必须带回 `owner_context_cursor`，不把重试旧调用视为已重新理解本人回复。

发送前继续检查配置、当前 turn、上下文游标及群成员关系。如果最后一次模型确认之后又发生变化，或投递重试期间本人补充了内容，草稿转私下确认，不重跑已经执行的原任务。消息编辑不是本次监听范围，主要处理新的群消息。

## 权限与投递

- 需要配置运行时令牌用于私下确认接口；缺少令牌时不能启用。需要机器人能接收到“只 @ 本人、没有 @ 机器人”的群消息，不能仅用 @ 机器人事件测试；平台未分发的消息无法由本功能补造。
- 接手与发送前通过 bot 身份读取群成员，确认双方在群中。权限不足、结果不完整或无法核实时不自动工作/发群；私下通知也重新核实成员，成员未知时只发送不含群原文/草稿的配置提示，对象已不在群时不转发内容。
- 协同原生会话从只读且无网络沙箱起步，包括可信发送人的协同请求；写入/联网逐项回调走既有实际发送人审批，可复用仍有效的原任务 turn 授权，每次放行仍重新检查协同状态。这里不是强制每项都人工确认；禁止的是原生整轮权限包直接绕过后续回调。普通直接 @ 机器人的可信执行策略不变，本地只读基线并非禁用所有原生读取工具。
- 关闭后再开启不会自动恢复旧 `handling/ready` 判定，模型需重新结合配置和上下文确认；已经结束的原任务不会被重放。
- 本人的新发言、开关变化、私下确认/忽略都会使尚未放行的审批与宿主调用失效；真正放行前再次校验。已经开始的外部操作只做有界收尾，不假设能撤销。
- 未提交决策、不回复或私下确认时，最终文本/附件不会自动发群。普通最终文字、附件、贴纸仍复用原有投递与幂等机制。
- 私下确认只发布审核的文本，版本失配需刷新。不得借确认草稿批准部署、修改原始请求者或重开已结束的执行任务；旧个人收件箱不会抢走同一消息改用本人身份发送。
- 私下通知必须有回执才标记成功，有稳定幂等键与重试上限。公开投递耗尽、服务重启或上下文变化会保留可审核草稿，不自动重放工作。`activeOwnerAssists` 计入后台通知和人工确认，重启前需等待为零。

## 验证边界

自动化使用新建临时数据库、模拟 CLI/模型和本机测试 API，覆盖实际原生输入参数、MCP 协议、本人追加、隔离、权限/审批竞态和投递恢复。模拟决策不等于真实模型分类准确率评测；没有合成真实飞书消息或执行真实部署。

本实例按事件去重；不同应用同时代理同一人的分布式协调不在范围内，建议每群只开启一个代理。全局关闭不覆盖单群显式开启，也不关闭已有的直接 @机器人或随机插话功能。
