# 消息时间与模型容量恢复

## 时间上下文

完整输入、增量输入和 steer 都包含一行北京时间，例如：

```text
时间(+08:00)：消息 2026-10-22 19:16
```

处理与发送不在同一分钟时，追加 `；当前 19:18`；跨天时保留当前完整日期。发送时间优先取 `message_at`，缺失或无效时依次取接收、创建时间；均不可用时只提供当前时间，不伪造发送时间。历史消息逐条保留分钟级时间、消息顺序及引用关系，不重复解释时区。

时间只是查询依据，不表示数据已同步至当前时刻，也不替代业务口径确认。

## 容量不足恢复

- 对原生 `turn/completed` 中的 `serverOverloaded`，在尚未调用工具且无待决审批时重试。
- 最多恢复三次，分别等待约 30、60、120 秒，并加入 ±20% 随机抖动；持续失败后回到原有失败处理。
- 保留同一个 Codex thread、模型与推理强度，仅追加简短恢复消息和刷新后的时间，不重放原始消息、历史、附件。
- 新 turn 清除旧 turn 授权，受限操作重新走审批。新消息等待恢复完成后再 steer，不发给已失败的 turn。
- 等待期间保留运行状态和心跳，原始错误、等待与恢复的 turn ID 写入任务日志；停止服务会取消等待。
- 已有工具活动、配额不足、认证错误或结果不明的请求超时不进入此容量恢复路径。尤其不会整轮自动重跑部署、合并或其他写操作。

`npm test` 使用临时数据库和本地模拟 App Server，覆盖恢复、次数耗尽、并发追加、审批隔离、模型固定及停止取消；不需要对真实飞书消息或运行数据库做测试写入。
