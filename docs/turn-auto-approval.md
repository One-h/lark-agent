# 飞书当前任务自动审批

## 行为

`turnAutoApprovalEnabled` 默认关闭，保存在本机 settings。Forge 设置页的“自动审批当前任务”同步这一开关。消息中出现“合并”等词不会直接转人工，也不会凭相似的正向历史记录跳过模型重新判定。已识别的高风险实际操作和既有受限先例仍走原边界。
开启后先按发送人、审批人、任务类型、目标和工作目录匹配最近的人工审批。PR 目标按站点和仓库匹配，数据查询需要明确的数据源。历史只采纳真正发送过卡片、已经作出决定的记录，排除过期和自动批准记录。最近同类拒绝或仅允许一次的决定会转人工；历史正向命中还要求相同的实际操作，并只放行该次操作。

数据源名称由本机 `turnAutoApprovalDataSources` 数组配置，默认空列表，不包含部署者或公司的预置数据库名。Forge 设置页提供“审批历史匹配的数据源”，也可通过 `PATCH /v1/settings` 保存。名称不区分大小写，支持字母开头及字母、数字、点、下划线、短横线；最多100项、每项64字符。请求必须明确命中一个配置数据源才复用其人工历史；未配置、多个来源或名称子串不匹配时交给模型。该列表不授予数据库访问权限，也不改变写操作的人工边界。
部署同样先匹配人工先例，按明确服务集合和环境区分；部署与部署状态查询使用不同任务类型。未说明环境只与其他同样未说明环境的记录匹配。目标不明确、混合查询与部署、带排除条件或多个环境的请求不进行简单历史复用，交给模型判断。当前及历史人工批准的操作都必须能提取匹配的目标；历史操作目标缺失或与请求不一致时交给模型，不回退到更旧的许可。不会把一个服务的许可用到另一个服务。

Codex 执行器可用 `lark_approval_plan` 登记整项任务的目标、预计影响和具体步骤，包括实际命令与目录或宿主能力及 JSON 参数。登记不授予权限。目标尚未核实时先只读核对，再更新计划，不猜参数。计划绑定当前消息、发送人、原生 turn 和审批人。

未命中历史时，独立审核模型同时查看当前请求、直接引用、提交的整项计划、当前操作及其申请理由、有限历史背景和最多三条人工先例。用设置中的 `turnAutoApprovalModel` 和 low 思考档位；不加载工作区守则、记忆、插件或 MCP，不调用 shell。审核员可批准本次操作、明确批准所列计划全部步骤，或转人工。没有完整可匹配的计划时，自动审批最多放行当前操作，不为后续动作授权。超出完整审核长度的操作不自动放行。
审核模型与飞书聊天模型分开保存。更改模型不需要开启自动审批；已经开始的审核保留原模型，新审核读取新配置，审计记录保留实际使用的模型。
审核进程限制技能目录的上下文预算，并逐项禁用用户配置中继承的 MCP。空的 `mcp_servers` 表会与用户配置合并，不能作为清空工具的依据；这些覆盖仅用于审核进程，不修改全局配置或聊天进程。Codex 内置指令仍占用输入 token，实际用量记录在审核结果中。

计划批准后，仅当实际操作与已审步骤的完整命令和目录、或能力与参数一致时，才复用计划授权。每个列出的步骤只提供一次对应的放行额度。计划变化、换消息、换人或新 turn 后不能用旧计划；没有匹配的步骤重新审核。范围判断不使用理由文本。运行时核对调用内容，不代替外部系统的状态或版本前置条件检查。

可核验的只读查询和本地任务登记仍可自动放行。常规部署保留明确目标的既有边界；实验流量等非例行线上写入，要求审批人明确确认实际操作或列出的计划。原有人工审批流程保留；有计划的卡片将“允许列出的计划”限制在显示的匹配步骤，不会形成无界的整轮授权。
审批人变更后旧授权不能复用。现代 App Server 请求必须同时匹配 thread 与 turn，迟到的旧 turn 请求不绑定到新任务。

审核超时（45 秒）、取消、模型失败、输出解析失败或开关在审核时关闭均沿用人工卡。自动审核路径没有匹配计划时，卡片只允许批准当前操作；关闭自动审核时未携带计划的既有人工作法不变。
审核模型必须对当前 Codex 登录账户可用；设置保存成功不代表模型调用成功。该模型不可用时，历史匹配仍可用，模型未命中部分会回到人工审批。

## 记录

有计划时，待审批卡、结果卡和自动授权通知把任务意图、计划、影响和当前操作分开显示。完整命令、参数和工作目录不在卡片中渲染。卡片中的自然语言是说明，不是权限边界。

`lark_turn_auto_reviews` 保存每次审核的范围、计划摘要、实际操作、决定来源、匹配审批 ID、模型、用量和应用时间。同一 turn 可有多个互相独立的审核。`GET /v1/approvals` 的 `autoReviews` 返回最近审核；本地执行日志另有 `approval/autoReview` 和实际操作的放行记录。
这些记录不是人工许可，不会递归成为免审批先例。判断错误时关闭设置即可恢复原审批流程。

## 自动授权通知

只有授权真正应用后才将通知加入 `lark_delivery_outbox`（`auto-approval` 类型），发送给本次记录中的审批人。每个审核记录有固定幂等键，已批准计划内的后续操作不重复发卡。单独重新授权的操作有独立的记录和通知；卡片明确区分当前操作、所列计划和旧版整轮授权。
通知发送采用异步 CLI，不阻塞授权及模型工具执行。失败最多重试八次，重启后继续处理持久化队列，且不会改变请求者的回复状态。媒体发送器只处理媒体类型，不会误处理通知卡。shadow 模式不向真实飞书发送通知，测试通过注入发送器验证。

## 验证

`npm test` 使用新建临时数据库，覆盖迁移、历史命中、单次授权、计划与实际范围绑定、未经批准的实际变更、宿主工具和模型错误回退。
`npx tsx scripts/verify-turn-auto-approval.ts` 使用真实 Codex 账户验证 PR、只读查询、部署及输入规则覆盖攻击；不执行这些示例操作、不发送飞书消息、不打开运行数据库。
可通过 `--model <模型 ID>` 验证其他审核模型，而不修改运行时设置。
短用例同时验证输入少于 8,000 token，防止默认技能目录重新膨胀审核上下文。
账户不支持审核模型时，可运行 `npx tsx scripts/verify-turn-auto-approval.ts --fallback` 验证真实模型错误会转入模拟的人工卡，拒绝后宿主操作不会执行。所有 SQLite 文件均在新建的临时目录中。
