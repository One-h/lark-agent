# 飞书当前任务自动审批

## 行为

`turnAutoApprovalEnabled` 默认关闭，保存在本机 settings。Forge 设置页的“自动审批当前任务”同步这一开关。消息中出现“合并”等词不会直接转人工，也不会凭相似的正向历史记录跳过模型重新判定。已识别的高风险实际操作和既有受限先例仍走原边界。
受限 Codex 回合的第一条原生命令或文件修改审批回调触发整轮决定；关闭自动审核时，运行时直接发整轮人工卡。开启时由审核模型先判断。已使用整轮决定的宿主工具和受限 ACP 调用可复用它。审核看用户原文、直接引用、上下文和当前实际操作。人工先例只作参考，不能直接授予新回合权限。可信直接会话按本机执行策略运行，宿主工具也不走 Lark 执行审批；身份、回合与业务服务校验仍照常。

数据源名称由本机 `turnAutoApprovalDataSources` 数组配置，默认空列表，不包含部署者或公司的预置数据库名。Forge 设置页提供“审批历史匹配的数据源”，也可通过 `PATCH /v1/settings` 保存。名称不区分大小写，支持字母开头及字母、数字、点、下划线、短横线；最多100项、每项64字符。请求必须明确命中一个配置数据源才复用其人工历史；未配置、多个来源或名称子串不匹配时交给模型。该列表不授予数据库访问权限，也不改变写操作的人工边界。
部署与部署状态查询使用不同任务类型。部署必须明确服务集合及环境，目标不明确或混合查询与部署时不会自动套用历史授权。一个服务的许可不能用到另一个服务。

任务模型按工具契约直接调用，既不登记审批计划，也不管理等待。运行时处理原生审批回调并回送结果。旧的 `lark_approval_plan` 入口仅兼容已有调用，不再展示或注入提示词；有无旧计划都不影响首次回调发起整轮授权。额外权限包不能替代实际操作的原生审批。

独立审核模型用设置中的 `turnAutoApprovalModel` 和 low 思考档位；不加载工作区守则、记忆、插件或 MCP，不调用 shell。模型只能批准整轮或让整个任务转人工；仅确认当前命令安全不能放行。超出完整审核长度的操作不自动放行。
审核模型与飞书聊天模型分开保存。更改模型不需要开启自动审批；已经开始的审核保留原模型，新审核读取新配置，审计记录保留实际使用的模型。
审核进程限制技能目录的上下文预算，并逐项禁用用户配置中继承的 MCP。空的 `mcp_servers` 表会与用户配置合并，不能作为清空工具的依据；这些覆盖仅用于审核进程，不修改全局配置或聊天进程。Codex 内置指令仍占用输入 token，实际用量记录在审核结果中。

普通任务首次触发时，审核模型按整轮意图给出决定，首个实际操作用于核对，既有审核前风险检查仍有效。模型返回 `approve_turn` 后，同一活动 turn、消息、请求人和审批人下的后续调用不再匹配计划或命令清单，也不重复审核。原生沙箱、宿主权限、业务校验和生命周期检查照常生效，不能将批准用于别的任务或回合。明确限制为只读的授权仍逐次核对约定的只读范围。

审批人明确选择「允许当前任务」后，普通任务在同一消息、发送人和活动 turn 内不再按首次计划逐项复审。标明限定只读的代答审批仍校验原授权范围；已识别的生产变更和其他高风险操作不借用这个规则扩权。原生权限、宿主校验和生命周期检查不变。

常规部署仍需明确目标；非例行线上写入需人工确认。新的人工卡只允许批准整轮任务或拒绝。白名单机器人的代答完成接手后，受支持的只读排查也可按整轮授权。允许在同一数据源和目标下调整日志过滤条件，以及受支持的单服务指标查询的聚合方式；其他数据源或未批准目标不复用授权。计划中的写入不进入这份授权。写入、部署和其他代答审批继续走原流程，原生整轮额外权限包仍不放行。
审批人变更后旧授权不能复用。现代 App Server 请求必须同时匹配 thread 与 turn，迟到的旧 turn 请求不绑定到新任务。

模型审核超时（45 秒）、失败或无法确定整轮范围时，转为一张整轮人工卡。任务结束或上下文失效时不放行；关闭自动审核会停止复用自动授权，不会撤销已经人工允许且仍有效的当前轮授权。运维可在启动时设置 `LARK_AGENT_AUTO_APPROVAL_GRANULARITY=operation` 暂时回退到旧版按操作自动审批。

## 记录

有计划时，待审批卡、结果卡和自动授权通知把任务意图、计划、影响和当前操作分开显示。完整命令、参数和工作目录不在卡片中渲染。卡片中的自然语言是说明，不是权限边界。

`lark_turn_auto_reviews` 保存审核范围、计划摘要、首个实际操作、决定来源、模型、用量和应用时间。新模式普通任务每个 turn 最多记录一次模型审核；各实际操作仍分别有执行日志。`GET /v1/approvals` 的 `autoReviews` 返回最近审核。
这些记录不是人工许可，不会递归成为免审批先例。判断错误时关闭设置即可恢复原审批流程。

人工等待超时为 `expired`，不等于人工明确拒绝（`rejected`）；策略拦截为 `blocked`。宿主调用直接返回实际原因。原生工具只反馈未放行时，模型可用 `lark_tools.lark_approval_status`（本轮 `context_token`、`input={}`）查看当前消息与回合的结果，不能查询其他回合或取得授权。超时不执行受限操作，也不在后台重试；可交付已完成的部分，待用户确认后重新发起。

## 自动授权通知

只有授权真正应用后才将通知加入 `lark_delivery_outbox`（`auto-approval` 类型），发送给本次记录中的审批人。整轮通知使用 turn 和审批人作为幂等键，后续操作不会再发卡；不回写历史通知。
通知发送采用异步 CLI，不阻塞授权及模型工具执行。失败最多重试八次，重启后继续处理持久化队列，且不会改变请求者的回复状态。媒体发送器只处理媒体类型，不会误处理通知卡。shadow 模式不向真实飞书发送通知，测试通过注入发送器验证。

## 验证

`npm test` 使用新建临时数据库，覆盖迁移、历史命中、单次授权、计划与实际范围绑定、未经批准的实际变更、宿主工具和模型错误回退。
`npx tsx scripts/verify-turn-auto-approval.ts` 使用真实 Codex 账户验证 PR、只读查询、部署及输入规则覆盖攻击；不执行这些示例操作、不发送飞书消息、不打开运行数据库。
可通过 `--model <模型 ID>` 验证其他审核模型，而不修改运行时设置。
短用例同时验证输入少于 8,000 token，防止默认技能目录重新膨胀审核上下文。
账户不支持审核模型时，可运行 `npx tsx scripts/verify-turn-auto-approval.ts --fallback` 验证真实模型错误会转入模拟的人工卡，拒绝后宿主操作不会执行。所有 SQLite 文件均在新建的临时目录中。
