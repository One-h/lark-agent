# 飞书当前任务自动审批

## 行为

`turnAutoApprovalEnabled` 默认关闭，保存在本机 settings。Forge 设置页的“自动审批当前任务”同步这一开关。
开启后先按发送人、审批人、任务类型、目标和工作目录匹配最近的人工审批。PR 目标按站点和仓库匹配，PR 编号不进入匹配键；数据查询需要明确的数据源。历史只采纳真正发送过卡片、已经作出决定的记录，排除过期和自动批准记录。最近同类拒绝或仅允许一次的决定会转人工。

数据源名称由本机 `turnAutoApprovalDataSources` 数组配置，默认空列表，不包含部署者或公司的预置数据库名。Forge 设置页提供“审批历史匹配的数据源”，也可通过 `PATCH /v1/settings` 保存。名称不区分大小写，支持字母开头及字母、数字、点、下划线、短横线；最多100项、每项64字符。请求必须明确命中一个配置数据源才复用其人工历史；未配置、多个来源或名称子串不匹配时交给模型。该列表不授予数据库访问权限，也不改变写操作的人工边界。
部署同样先匹配人工先例，按明确服务集合和环境区分；部署与部署状态查询使用不同任务类型。未说明环境只与其他同样未说明环境的记录匹配。目标不明确、混合查询与部署、带排除条件或多个环境的请求不进行简单历史复用，交给模型判断。当前及历史人工批准的操作都必须能提取匹配的目标；历史操作目标缺失或与请求不一致时交给模型，不回退到更旧的许可。不会把一个服务的许可用到另一个服务。

未命中时使用设置中的审核模型（`turnAutoApprovalModel`，默认 `gpt-6.1-sol`）、low 思考档位、独立 ephemeral 会话判断一次。输入仅包含当前请求、第一条待执行操作、工作目录及最多三条人工先例。审核会话不加载工作区守则、记忆、插件或 MCP，禁用 shell 工具；只输出 `approve_turn` / `manual` 及一句理由。审核模型尝试调用工具或返回异常结果时转人工。
审核模型与飞书聊天模型分开保存。更改模型不需要开启自动审批；正在进行的审核及其 turn 保留开始时的模型，下一轮审核读取新配置，审计记录保留实际使用的模型。
审核进程限制技能目录的上下文预算，并逐项禁用用户配置中继承的 MCP。空的 `mcp_servers` 表会与用户配置合并，不能作为清空工具的依据；这些覆盖仅用于审核进程，不修改全局配置或聊天进程。Codex 内置指令仍占用输入 token，实际用量记录在审核结果中。

批准后按同一发送人、同一 turn 复用授权。后续命令不再逐条审核。新 turn 或新发送人重新判断；机器人发送人与普通发送人仍使用现有身份与会话隔离。部署不再固定转人工：模型可以批准目标和范围明确的常规部署，包括指定应用的 main 镜像发布、状态刷新、同步与验证。只读状态检查及 Argo 缓存刷新也可以通过。回滚、推送/合并代码、代码修复、删除资源和数据库写入等仍保留原有人工边界。`forge.deploy.production` 可以走自动审核；其他外部写入宿主工具仍保留人工审批。
审批人变更后旧授权不能复用。现代 App Server 请求必须同时匹配 thread 与 turn，迟到的旧 turn 请求不绑定到新任务。

审核超时（45 秒）、取消、模型失败、输出解析失败或开关在审核时关闭均沿用人工卡。已有人工 turn 授权保持原行为。
审核模型必须对当前 Codex 登录账户可用；设置保存成功不代表模型调用成功。该模型不可用时，历史匹配仍可用，模型未命中部分会回到人工审批。

## 记录

`lark_turn_auto_reviews` 保存决定来源、匹配审批 ID、审核模型、用量和实际应用时间。`GET /v1/approvals` 的 `autoReviews` 返回最近审核。命令审批的执行记录中另有 `approval/autoReview` 事件。
这些记录不是人工许可，不会递归成为免审批先例。判断错误时关闭设置即可恢复原审批流程。

## 自动授权通知

只有授权真正应用后才将通知加入 `lark_delivery_outbox`（`auto-approval` 类型），发送给本次记录中的审批人，而不是请求者或所有可信人。每个审核记录有固定幂等键，因此同一 turn 的后续操作不会重复通知；不同发送人的授权分别通知。卡片展示请求者、原始请求、历史/模型来源、理由和授权时间，明确说明授权不代表任务或部署已经完成，无需再次点击批准。
通知发送采用异步 CLI，不阻塞授权及模型工具执行。失败最多重试八次，重启后继续处理持久化队列，且不会改变请求者的回复状态。媒体发送器只处理媒体类型，不会误处理通知卡。shadow 模式不向真实飞书发送通知，测试通过注入发送器验证。

## 审核策略变更说明

- 目标：从固定排除部署改为“历史优先、未命中由模型判断”，并支持部署状态查询。
- 旧问题：部署关键词和审核提示词双重拒绝，检查/刷新操作也容易被当作部署风险。
- 输入与输出：仍仅使用当前请求、首个操作、目录与最多三条真实人工先例，保持 `approve_turn` / `manual` 输出契约，不增加执行工具。
- 保持不变：最近拒绝/单次许可优先、身份与 turn 隔离、解析/超时失败转人工、审核模型配置和既有高风险边界。
- 验收：指定服务部署和状态检查可通过；不明确目标、破坏资源和规则覆盖攻击转人工；查询先例不能授权部署；自动通知一次、失败可恢复。

## 验证

`npm test` 使用新建临时数据库，覆盖关闭、历史命中、最近拒绝、仅单次授权、跨身份/目标/目录、同 turn 并发合并、模型错误回退、宿主工具和设置持久化。
`npx tsx scripts/verify-turn-auto-approval.ts` 使用真实 Codex 账户验证 PR、只读查询、部署及输入规则覆盖攻击；不执行这些示例操作、不发送飞书消息、不打开运行数据库。
可通过 `--model <模型 ID>` 验证其他审核模型，而不修改运行时设置。
短用例同时验证输入少于 8,000 token，防止默认技能目录重新膨胀审核上下文。
账户不支持审核模型时，可运行 `npx tsx scripts/verify-turn-auto-approval.ts --fallback` 验证真实模型错误会转入模拟的人工卡，拒绝后宿主操作不会执行。所有 SQLite 文件均在新建的临时目录中。
