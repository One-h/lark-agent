# 执行配置同步

- `GET/PATCH /v1/settings` 的 `trustedExecutionEnabled` 是可信执行总开关。独立 Agent 默认关闭；Forge 启动握手和设置保存会同步其本地持久配置。发送人在可信名单内（或是审批接收人）且此开关开启时，才可使用可信会话；原生 Codex 与宿主工具使用同一判定。
- `workspaceRoot` 必须是可读、可进入的现有绝对目录。保存后写入 Agent 数据库，重启优先使用数据库值，而不是旧环境变量。工作区改变后，已有 Codex 会话在下一轮以新目录恢复并刷新完整工作区说明；历史消息和会话 ID 保留。数据库、附件和任务包不随工作区移动。
- 更改目录、可信开关、可信名单或审批人时必须没有运行、准备、排队中的 Codex 任务或在途宿主调用，否则返回 `409 CODEX_TURN_ACTIVE`，不部分保存。名单按去重后的集合比较，重复保存相同有效值不受影响。旧任务不会被强行中断。
- 人设和全局提示词仍以 turn 为单位保留快照。进行中 turn 的追加消息沿用原快照，下一 turn 或新任务读取新配置。

配置保存需要核对返回的有效值；旧 Agent 不支持新字段时，Forge 会明确报错，不以 HTTP 200 代替配置生效确认。测试只使用临时数据库及模拟 App Server/宿主服务，不改动现有用户数据。

## 每轮执行配置

消息任务目录中的 `execution-configs.jsonl` 追加保存每次已接受的 `turn/start` / `turn/steer` 参数。新建、恢复和认证重试的轮次分别记录；轮内追加沿用原轮次快照，不读取后来更改的模型、人设或思考等级。

消息详情的 `executionConfigs` 直接读取这些轻量元数据，不加载完整 prompt/stdout。历史无记录或字段未知时不使用当前设置回填。记录只包含模型、思考等级、基础权限策略、工作区、人设元信息和全局提示词 Hash，不复制提示词、工具输入、令牌或凭据，也不增加模型输入 token。

来源 `accepted-request` 表示 App Server 已接受的提交参数，不是服务内部推理强度的独立证明；基础沙箱策略不替代执行过程中的逐项审批记录。

## 严格保存

`/v1/settings` 的全部可写运行配置先统一校验，再在一次事务中保存。未知字段、类型错误或越界值返回 400；布尔 false 和数值 0 不会被当作缺省值。监听器等进程副作用在持久化后执行，失败会明确报错供调用方补偿，不假报保存成功。

Forge 设置页将同一次提交的全部飞书运行字段合并为一次 PATCH，并核对回包和独立 GET；本地事务失败时补偿本批远端值。基础配置、恢复与启动同步复用同一确认入口。人设、提示词内容仍由其独立接口编辑，保留既有轮次快照语义。

## 启动等待与失败通知

内部阈值 `larkCodexStartupStallMs` 默认 60000，表示首次工作事件迟迟未出现时开始回查，不是任务执行时限，也不是新增的环境变量配置。运行器读取原生 thread 状态及最近 10 个 turn，精确匹配当前 turn；原生仍在运行时保留等待，不发送 interrupt、不重放请求。每个任务最多每分钟回查一次，单次在途查询不会重复发起。

原生明确失败或中断时按真实终态结束并发送安全的失败通知；发现已完成但终态事件漏收时，恢复该轮最终答复。查询超时、协议不支持、缺少目标轮次或状态矛盾均视为未知，记录后继续核查，不当作失败。迟到查询不能覆盖已完成、已开始工作或已切换轮次的任务。

失败通知复用现有文本幂等键及投递重试，不向飞书外发原始错误、路径或凭据。启动失败、恢复失败和意外 App Server 退出同样会通知；显式停止运行器仍保持原有的静默关闭行为。

重复投递的入站事件只更新消息元数据，不自动重跑已失败请求；手动重试入口保留。认证恢复后的新 turn 重新计算启动等待，原生容量错误仍使用既有退避恢复策略。
