# 图片与文档附件工具

## 调用契约

内置 `lark_stickers` stdio MCP 提供 `attach_files`，表情包仍使用原有 `search` / `select`。
工具服务名称保留兼容；不需要用户在 Codex 全局配置中额外注册 MCP。

```json
{
  "context_token": "当前消息提示词中的32字符令牌",
  "files": [
    { "path": "report.csv", "name": "视频链接.csv" },
    { "path": "chart.png" }
  ]
}
```

- 文件必须已经生成在当前消息的 `output/` 目录；`path` 是该目录内的相对路径。
- `name` 可选，必须是保留原扩展名的普通文件名，不接受目录、控制字符或其他接收人参数。
- 累计最多登记 8 个附件，重复源路径更新而不叠加；`files=[]` 清空当前消息的登记。
- 图片上限 10 MiB，其他文件上限 50 MiB；拒绝空文件、目录、越界路径、指向目录外的软链接。
- 成功返回 `status=staged`、附件 ID/名称/类型/大小和 `sent=false`，仅表示登记成功。
- 服务端保存受限目录中的内容快照及摘要。原文件后续改动不改变已登记内容；要更新附件应重新调用工具。
- 不扫描输出目录推测要发送什么，不把全部文件自动交付给用户。

## 模型输入和生命周期

全量与增量消息输入都提供简短的 `attach_files` 用法、当前 `output` 路径和当前上下文令牌。
这些说明独立于人设与表情包策略；关闭表情包不关闭图片/文档能力。
模型登记后使用普通最终回复，不再拼接媒体标签，也不能把 staged 说成已发送。

调用经本机 HTTP `/v1/internal/attachments/register` 转发，需要进程间 token、
loopback 来源及当前活动消息的 context_token。已配置 runtime token 时复用它；独立机器人未配置共享 token 时，
只为附件 MCP 使用进程内随机 token，不写入文件/数据库，也不为宿主接口开放免鉴权。
过期、跨消息或已完成 turn 的调用被拒绝。
工具不能选择任意 chat_id 或收件人，登记时不会发送飞书消息。

仅在原生 turn 正常结束后才提交已登记附件。任务失败、取消或明确 no-reply 时不投递。
即使正文为空也允许只交付附件。同一 turn 内新增 steer 消息不会把此前登记的附件改发给后来的消息：
附件仍引用其登记时绑定的原消息；既有文本回复路由不变。

## 可靠投递与完成信号

- 图片继续合并为图文消息；普通文档逐个发送，复用现有 CLI 和持久 outbox。
- 有最终正文时，图片/文档和表情包都等待对应最终文字回执；纯附件不需要正文回执。
- 发送前再次校验快照边界与摘要；摘要异常时不上传。
- 幂等键绑定 turn、目标消息和附件路径；成功记录不会重复发送。临时上传失败有界重试，重启后从 outbox 继续，不重跑模型。
- 附件最终失败时，给原消息排入一次可靠的失败通知；通知本身也有幂等及最多 8 次重试。
- 完成 reaction 依赖实际文字/附件交付；上传失败不能变为 DONE。DONE 仍仅代表本轮处理结束，不证明独立业务验证。

## 旧协议兼容

继续支持有效的 `<lark-media>` / `<forge-media>` 声明，使用相同文件校验和投递队列。
本条消息调用过工具时，以工具登记的完整选择为准，旧标签只移除、不补发未登记文件；`files=[]` 同样覆盖旧声明。
不完整的旧声明会被移除并明确报告附件校验失败，不再原样发出协议文本或静默当作无附件成功。
既有表情包和历史图片工具的参数、权限及行为保持不变。

## 验证范围

`npm test` 使用新建临时数据库、fake Codex/飞书 CLI、真实 MCP stdio 客户端和本机临时 HTTP 服务，
覆盖登记、鉴权、多图/文档、文字失败重试、纯附件、取消、steer 收件人、内容快照、通知与去重。
这些测试不向真实飞书发送消息，不调用真实付费模型，不等同于上线后的真实聊天验收。
